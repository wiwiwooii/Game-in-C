# Руководство по созданию игры шахматы.

За основу руководства взят видео курс, который был прикреплен к вариативной части задания. Автором курса является: Bluefever Software. Все права курса принадлежает автору, это лишь краткое руководство по его курсу. Данный гайд временно содержит восемь первых уроков.

## Урок 1. 

Урок посвящен дополнительным материалам, которые могут пригодиться для исследования уже существующих шахматных движков, а также форумов для программистов, которые создают шахматы. Там можно найти много дополнительной информации. Автор курса выделяет несколько ресурсов:
       1. talkchess.com
       2. chessprogramming.com.
       3. computerchess.org.uk

Для создания собственных шахмат выделим цел на курс: разработать простой, но эффективный движок, способный победить 90% игроков.


## Урок 2. 

Для компиляции понадобится создать makefile. Помимо этого создадим еще несколько файлов: vice.c и defs.h. 

Шахматная доска представляется массивом целых чисел, каждое из которых имеет значения: пустой квадрат, фигура или удалённая клетка. Одной из проблем генерациии ходов являются ситуации, когда фигура выходит за пределы доски. Для решения этой проблемы предлагается увеличение массива и добавление граничных квадратов со значением "вне доски". Также понадобятся дополнительные "защитные" ряди из-за особенностей движений некоторых фигур, например, коня. 

Таким образом, шахматная доска будет представлена массивом из 120 чисел. Также необходимо добавить счётчик для правила 50 ходов, отслеживание проходных клеток, направления движения и хода игры.

## Урок 4

Создадим структуру board с массивом целых чисел pieces размером 120 элементов. Для создания пешенк на доске используем беззнакового 64-битного целого числа pawns. Если на поле стоит пешка соответствующего цвета, значение равно 1, иначе — 0. Дополнительно организуем хранение координат полей королей белых и черных на доске, учет текущей стороны, которая ходит, активного поля, хранения счётчика ходов и текущего поиска. 

Реализуем хранения истории ходов. Нужно будет хранить общее количество половинных ходов в партии. 

Также понадобится организация больших и малых фигур. Хранение количества больших фигур ладьи и ферзи и малых фигур слоны и кони по три значения для каждой стороны. Эти данные необходимы для оценки позиции в ничейном эндшпиле.

Код урока: 

```
typedef struct {

	int pieces[BRD_SQ_NUM];
	int play; //half moves current 
	int hisPlay; //total half move

	int castlePerm; //разрешение на рокировку

	U64 posKey; //unic key for each positions

} S_BOARD;
```

## Урок 5 

В этом уроке нам предстоит сделать рокировку, а точнее разрешение на него.

Добавление разрешений на рокировку: белого короля — 1, белого ферзя — 2, чёрного короля — 4, чёрного ферзя — 8. Разрешения на рокировку представлены четырьмя битами в одном целом числе. Например, 1001 означает, что белые могут сделать рокировку на королевском фланге, но не на ферзевом.

Определим максимальное количество ходов в игре. За максимальное количество примем значение 248. Этого количества ходов будет достаточно для хранения истории игры. 

• Максимальное количество ходов в игре определено как 248.
• Это количество ходов достаточно для хранения истории игры.

Создадим массив истории и структуру "отмены" для хранения информации об отмене хода. Массив истории будет иметь размер равный максимальному количеству ходов. При каждом ходе будет сохраняться инфорамция о нем, разрешении на рокировку, статусе правила пятидесяти ходов.

Следующий шаг проверка повторения позиций с помощью ключей позиций. Если позиция повторяется три или более раз, игра заканчивается вничью.

Пример новой структуры, массива и разрешения на рокировку, которые добавляются в структуру из предыдущего урока:
